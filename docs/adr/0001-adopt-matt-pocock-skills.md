# Matt Pocock Skillsを選択的に導入する

- 状態: 採用
- 決定日: 2026-11-14
- 関連課題: [#18](https://github.com/yamaoyu/dog-health/issues/18)

## 背景

dog-healthでは、プロジェクト固有の `create-issue`、`start-issue`、`create-pr` を使って課題駆動の開発フローを運用している。一方、要求整理、テスト駆動開発、不具合調査、レビュー、振り返りには共通手順がなく、すべてを独自スキルとして保守することも避けたい。既存フローを維持しながら不足する工程を補い、上流の変更で開発フローが意図せず変わらない方法が必要である。

## 決定

既存のプロジェクト固有スキルは維持し、不足する工程にMatt Pocock Skillsを選択的に導入する。要求整理には `grill-with-docs`、実装には `tdd`、不具合調査には `diagnosing-bugs`、レビューには `code-review`、振り返りには `retro` を使い、補助スキルとして `grilling`、`domain-modeling`、`writing-for-agents` を使う。`grill-with-docs` が要求する `domain-modeling` も依存関係として導入する。

導入したスキルは `.agents/skills/` に保存してGitで管理する。取得元は [mattpocock/skills](https://github.com/mattpocock/skills) のコミット [`5863806dd4e15c63174bee4e7515a4256792ecfa`](https://github.com/mattpocock/skills/commit/5863806dd4e15c63174bee4e7515a4256792ecfa) とし、MITライセンスの条件に従う。自動更新は行わず、更新先コミットとの差分とスキル間の依存関係を確認してから明示的に更新する。

Matt Pocock Skillsは原則として上流の内容と言語を維持し、dog-health固有のルールは既存スキルと `AGENTS.md`、`docs/` で管理する。このプロジェクトで作成するドキュメントは日本語で記述し、外部から取得したスキルやライセンスは原文のまま管理する。用語集はドメイン用語、ADRは設計判断、要件文書はプロダクト要件、課題は実装範囲、スキルは繰り返し使う手順を扱う。

## 選択しなかった案

- **独自スキルだけを使う:** 不足する工程をすべて独自に設計、検証、保守する負担が増えるため採用しない。
- **Matt Pocock Skillsをすべて導入する:** 既存スキルとの責務重複と、最小実用製品に不要な運用の複雑化を招くため採用しない。
- **プラグインとして自動更新する:** 上流の変更がレビューなしで開発フローへ影響し、プロジェクト内で同じ動作を再現しにくくなるため採用しない。

## 結果

要求整理からプルリクエスト作成後の振り返りまで、既存スキルとMatt Pocock Skillsを組み合わせた共通フローを利用できる。プロジェクト内にスキルのスナップショットを持つため再現性が得られる一方、上流更新の確認とスキル間の依存関係の管理が必要になる。小さく明確な変更では、目的に不要なスキルを省略してよい。

## 運用・見直し

更新時は、現在の上流コミットと更新先コミットの差分、参照ファイル、スキル間の依存関係、Codexからの認識を確認し、新しいコミットを記録する。スキルの責務重複、運用負荷、互換性の問題、利用するAIエージェント環境の変更が生じた場合は、この判断を見直す。
