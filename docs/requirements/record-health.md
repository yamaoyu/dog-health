# 健康記録要件

このドキュメントは、犬のevent登録と履歴表示に関する画面、操作、期待動作を管理する。eventのdatabase構造は `../schema.md` を参照する。

## 目的

飼い主が犬の日々の活動を記録し、日・週・月単位で振り返れるようにする。

## MVPで扱うEvent

- `walk`: 散歩
- `food`: ご飯
- `toilet`: トイレ

eventは発生日時、任意のメモ、種別ごとの詳細を持つ。event typeは固定し、ユーザーによる追加・編集は行わない。

## ユースケース

### Eventを登録する

前提:

- login中であり、犬一覧に対象の犬が表示されている。

画面と操作:

1. 対象の犬のメニューからevent作成を開く。
2. eventの種類を選択する。
3. 日時、任意のメモ、種類ごとの詳細を入力する。
4. 「イベントを登録」を押す。

共通の期待動作:

- 日時は必須とし、初期値には現在日時を表示する。
- メモは任意かつ1000文字以内とする。
- 登録に成功した場合はモーダルを閉じ、対象の犬名を含む完了メッセージを表示する。
- 入力またはAPIエラーはモーダル内に表示する。
- 登録中はモーダルを閉じず、重複送信を防ぐ。

種類ごとの入力:

| 種類 | 入力項目 | 条件 |
| --- | --- | --- |
| 散歩 | 距離、時間 | いずれも任意。距離は0〜10kmで小数第1位まで、時間は合計0〜1439分 |
| ご飯 | メニュー、量 | いずれも任意。量は0〜1000gの整数 |
| トイレ | 種類、状態 | 種類は「おしっこ」「うんち」、状態は「良好」「いつも通り」「気になる」から選択 |

選択したevent typeに属さない詳細項目は送信しない。

利用するAPI:

- `POST /events`

### 今日のEventを確認する

画面と操作:

1. 犬一覧で対象の犬の「今日のイベント」を開く。

期待動作:

- アプリケーションのtimezoneにおける当日のeventを表示する。(本アプリではAsia/Tokyo固定とする)
- 種類、時刻、種別ごとの詳細、メモを表示する。
- 0件の場合は空の状態を表示する。
- 取得に失敗した場合はモーダル内にエラーを表示する。
- 複数の取得が重なった場合、現在選択中の犬以外の結果で表示を上書きしない。

利用するAPI:

- `GET /events`（`period=day`）

### Event履歴を確認する

画面と操作:

1. 対象の犬のメニューからevent一覧へ移動する。
2. 週表示または月表示を選ぶ。
3. 必要に応じて前後の期間へ移動し、event typeで絞り込む。

期待動作:

- 初期表示は今日を含む週とする。
- 週表示は月曜日から日曜日までの7日間を表示する。
- 月表示は対象月のeventを日付ごとに表示する。
- 前後移動により、週単位または月単位で表示期間を変更する。
- 「すべて」、散歩、ご飯、トイレで絞り込める。
- eventは日付ごとにまとめ、種類、時刻、詳細、メモを表示する。
- 0件の場合は空の状態を表示する。
- 取得に失敗した場合はエラーを表示する。
- 複数の取得が重なった場合、古いresponseで現在の一覧を上書きしない。

利用するAPI:

- `GET /events`（`period=week` または `period=month`、任意の `event_type_code`）

## 対象外

- eventの更新・削除
- custom event type
- 症状、服薬、通院など固定3種類以外のevent
- 添付ファイルや画像
- 集計、グラフ、傾向分析
- 通知やリマインダー
- AI診断
- 複数の犬を横断したevent一覧
