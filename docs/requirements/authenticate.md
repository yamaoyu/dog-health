# 認証・ログイン要件

このドキュメントは、MVPにおける飼い主の識別、ログイン、ログアウトの画面と期待動作を管理する。認証方式の技術方針は `../architecture.md`、飼い主情報の登録・更新は `manage-dogs-owners.md` を参照する。

## 目的

登録済みの飼い主を簡単に識別し、その飼い主に紐づく犬を操作できる状態にする。

## MVPの方針

- passwordは使用せず、login IDだけで飼い主を識別する。
- login状態はフロントエンドのメモリ上だけで保持する。
- ページを再読み込みするとlogin状態は失われる。
- 未loginで保護された画面へ移動した場合は、login画面へ遷移する。
- JWT、cookie sessionなどの本格的な認証は扱わない。

## ユースケース

### Loginする

前提:

- 飼い主が登録済みである。

画面と操作:

1. ユーザーが `/login` を開く。
2. 4文字以上20文字以下のlogin IDを入力する。
3. 「ログイン」を押す。

期待動作:

- login IDに一致する飼い主が存在する場合、その飼い主を現在のユーザーとして保持し、犬一覧へ遷移する。
- 入力が空または文字数の範囲外の場合、画面にエラーを表示し、APIを呼び出さない。
- 一致する飼い主が存在しない場合、APIのエラー内容を画面に表示する。
- 送信中はボタンを無効化し、重複送信を防ぐ。

利用するAPI:

- `POST /sessions`

### 飼い主登録後にLoginする

画面と操作:

1. 飼い主登録が完了する。
2. login画面へ遷移する。

期待動作:

- 登録したlogin IDが入力済みの状態になる。
- 登録完了メッセージを表示する。
- ユーザーがlogin操作を行うまでlogin状態にはしない。

### Logoutする

画面と操作:

1. login中のユーザーがユーザーメニューを開く。
2. 「ログアウト」を押す。

期待動作:

- メモリ上のlogin情報を削除する。
- login画面へ遷移する。

### 保護された画面へ移動する

対象画面:

- `/dogs`
- `/dogs/:dogId/events`

期待動作:

- login中なら対象画面を表示する。
- 未loginならlogin画面へ遷移する。

## 対象外

- passwordの登録・照合・再設定
- JWT、cookie session、refresh token
- 権限管理
- 多要素認証
- 外部identity providerとの連携
- 永続的なlogin状態
- 本番環境向けのsecurity設計
